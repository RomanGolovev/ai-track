# Life OS

Однопользовательский локальный Next.js App Router проект. Node.js >=22.13 (рекомендуется 24 LTS), npm.

- `app/page.tsx`: интерактивный интерфейс на русском, без демонстрационных записей.
- `app/globals.css`: адаптивная тёмная тема; Tailwind подключён через PostCSS.
- `app/api/data`: чтение/запись с валидацией и optimistic locking.
- `app/api/chat`: серверный клиент локальной Ollama, контекст из актуальной базы.
- `lib/model.ts`: типы, проверка резервных копий, расчёт окон.
- `lib/db.ts`: SQLite (`node:sqlite`), WAL; `data/life-os.sqlite`.
- `lib/prompt.ts`: системные правила наставника.

Используйте существующую рабочую копию: облачные задачи уже изолированы, worktree без запроса не создавать. Установка: `npm ci`. При ограниченном домашнем каталоге: `npm ci --cache /workspace/.npm-cache`.

Проверки перед завершением: `npm test`, `npm run typecheck`, `npm run build`. Для ручной проверки: `npm run dev`, первый запуск, создание/редактирование/перенос/удаление события и задачи, дневник, экспорт/импорт, чат с недоступной Ollama. Проверяйте мобильную ширину. Не подменяйте реальную интеграцию ИИ статическими ответами.

Ollama по умолчанию: http://127.0.0.1:11434, модель qwen3:4b. Клиент — lib/ollama.ts. Платные API не используются. Не добавляйте API-ключи в клиент, git, логи или резервные копии. Не логируйте дневник и переписку. Не меняйте расписание из чата без решения пользователя. Не выдумывайте расписание, работу или историю. Сохраняйте обратную совместимость резервных копий; новые структуры требуют миграции и тестов. Не стирайте пользовательскую базу для тестов. Это локальное приложение без авторизации: публичное размещение требует отдельной защиты.

Недельное планирование: `app/weekly-planner.tsx`, сервер `app/api/week/route.ts`, правила/типы/окна `lib/weekly.ts`. `State.weekPlans` необязателен для старых копий. Никогда не применяйте черновик без подтверждения; фиксируйте исходные блоки и baseline задач для сравнения. Ночные смены переходят через полночь; конец календарного дня допускает `24:00`. Отсутствие отметки факта не означает провал. Адаптация рекомендаций происходит через дневник и предыдущие планы в контексте, не через обучение модели.
