# Life OS

Локальный персональный планировщик на русском: Next.js, TypeScript, Tailwind CSS, SQLite и локальная Ollama без оплаты запросов. Для одного пользователя, без облачной базы и выдуманных событий.

## Запуск

Нужен **Node.js 24 LTS** (минимум 22.13) и npm. SQLite встроен в Node.js, отдельный сервер базы не нужен. Node может выводить предупреждение об экспериментальном статусе `node:sqlite`.

```bash
cd ai-track
npm ci
npm run dev
```

Откройте `http://localhost:3000` на своём компьютере. В облачной среде используйте доступ к приложению, который предоставляет ваша платформа. При недоступном домашнем каталоге npm выполните `npm ci --cache /workspace/.npm-cache`.

Для production-сборки:

```bash
npm run build
npm start
```

## Первые шаги

1. При первом запуске укажите имя, сон, дорогу и известные ограничения: время пар, вождение, тренировки, предполагаемые смены. Неизвестное можно оставить пустым. Это контекст, а не автоматическое создание событий.
2. В календаре добавьте конкретные события и категории. Поддерживаются день/неделя; пересечения отмечаются красным. Нажмите событие для редактирования, переноса или удаления. Ночные события разделяйте на два дня.
3. Добавьте задачи: описание, день/дедлайн, длительность, приоритет. Галочка отмечает выполнение; нажатие названия позволяет перенести дату. На главной показываются до трёх незавершённых задач с приоритетом важных.
4. Вечером заполните дневник: энергия, настроение, усталость и текст. Кнопка обсуждения подставляет запрос наставнику — отправьте его после проверки.
5. В настройках обновляйте приоритеты и ограничения, экспортируйте JSON. Импорт полностью заменяет данные после подтверждения; сначала сохраните резервную копию.

Календарные свободные окна показываются с 08:00 до 23:00 и не учитывают автоматически дорогу, еду, сон, отдых и задачи: добавляйте для них события. Статистика часов основана на календаре и показывает план, не измеренный факт. События категории «Работа» считаются записями работы, не обязательно подтверждёнными сменами. Пересечения суммируются; процент выполнения считается по текущим датам задач, поэтому переносы его меняют.

## Бесплатный ИИ через Ollama

Установите [Ollama](https://ollama.com/download) на тот же компьютер, где запускаете Life OS. Затем выполните:

```bash
ollama pull qwen3:4b
ollama serve
```

Если приложение Ollama уже работает в фоне, `ollama serve` повторно не нужен. Первое скачивание требует интернета и нескольких гигабайт диска. Ответы создаются на вашем компьютере без API-ключа и оплаты запросов; скорость зависит от памяти и процессора/GPU. После скачивания модель может работать без интернета. Для слабого компьютера попробуйте `ollama pull qwen3:1.7b`.

По умолчанию Life OS подключается к `http://127.0.0.1:11434` и использует `qwen3:4b`. Настройки необязательны; чтобы изменить модель или адрес, создайте `.env.local`:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:1.7b
```

Перезапустите Life OS после изменения файла. OpenAI API больше не используется. Контекст передаётся только настроенному серверу Ollama: задачи, события, настройки, последние 30 записей дневника и 20 сообщений. Для сохранения приватности оставьте адрес локальным. Часовой пояс и время берутся из браузера. Наставник предлагает изменения, вы применяете их вручную.

**Если Life OS запущен в облаке:** адрес 127.0.0.1 означает облачную машину, а не ваш ноутбук. Самый простой бесплатный вариант — запустить и Life OS, и Ollama на своём компьютере. Не открывайте Ollama в интернет без защиты.

Если Ollama выключена или модель не загружена, чат показывает инструкцию, остальные функции продолжают работать. Кнопка **«Контекст для Codex»** скачивает текст для передачи в Codex в рамках доступных вам лимитов. Резервные копии и старая история чата сохраняются.

## Данные и безопасность

`data/life-os.sqlite` создаётся автоматически при первом обращении к API. Данные переживают перезапуск. Не удаляйте каталог `data`; включайте его в постоянный том при использовании контейнера. Для переноса используйте JSON-экспорт, содержащий историю чата. Импорт проверяется на сервере; одновременные изменения из разных вкладок отклоняются с просьбой обновить страницу.

Это локальное приложение **без входа и разграничения доступа**. Команды слушают `0.0.0.0` для совместимости с облачной средой; не открывайте порт в недоверенную сеть. Для привязки только к своему компьютеру: `npx next dev --hostname 127.0.0.1`. Публичный хостинг требует авторизации, ограничения запросов и HTTPS. Данные в SQLite и JSON не зашифрованы. Уведомления, повторяющиеся события, синхронизация внешних календарей и автоматическое применение предложений не входят в MVP.

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

Тесты проверяют импорт и расчёт свободных окон; проверка типов и production-сборка проверяют совместимость проекта. Тесты клиента Ollama используют тестовый HTTP-сервер и проверяют протокол и ошибки. Реальную генерацию проверяйте с установленной Ollama и загруженной моделью.

## Умное планирование недели

Откройте **«План недели»** (обычно в воскресенье), выберите понедельник и опишите точные обязательства следующей недели. Для ночной смены укажите оба дня: «пятница 22:00 — суббота 06:00». Отметьте неизвестные часы и дела, которые можно перенести. ИИ получает текущий календарь, незавершённые задачи, приоритеты, дневник до начала выбранной недели (до 30 записей) и четыре предыдущих варианта с отметками факта. Пары не должны автоматически повторяться с прошлой недели.

Ollama возвращает структурированный черновик: блоки с причинами, объяснение распределения и предупреждения. Некорректные ответы отклоняются, календарь не меняется. Проверьте результат и нажмите **«Подтвердить и добавить в календарь»**. Существующие события остаются. Один вариант нельзя применить повторно. Новый вариант не заменяет старый автоматически: при изменениях используйте календарь и проверяйте конфликты.

Свободные окна рассчитаны на все сутки по объединению календаря и предложения. Они не считаются временем для новых дел, пока не выделены сон, еда и дорога. Ночные блоки продолжаются в следующий день, а в календаре разделяются по полуночи без потери минуты; 24:00 означает конец суток. Проверки предупреждают о пересечениях, более 10 часах дел в предложении и коротком промежутке между ночной сменой и следующим делом предложения. Это вспомогательные проверки, не гарантия оптимальности: проверяйте и существующий календарь.

После принятия отмечайте в плане **«Выполнено / Частично / Не получилось»**, фактические минуты и причину отклонения. Сравнение использует сохранённые блоки и снимок задач на момент генерации, поэтому последующие переносы не переписывают исходную цель. Неотмеченные блоки остаются неизвестными. На следующих неделях ИИ учитывает эти сведения и дневник: это адаптация через контекст, не обучение весов модели. История планов и факта входит в SQLite и JSON-резервные копии; старые копии без недельных планов по-прежнему импортируются. Небольшая локальная модель может ошибаться или не выдать правильный JSON — уточните ввод и повторите запрос. Модель в облачной среде отдельно не устанавливается.

Проверка полного недельного сценария: после `npm run build` выполните `npm run test:week-flow`. Тест запускает отдельный сервер и временную SQLite через `LIFE_OS_DATA_DIR`, не затрагивая вашу базу; Ollama заменена тестовым HTTP-сервером. Проверяются черновик, принятие, ночные смены, факт, резервная копия, передача истории и отказ при некорректном ответе.
